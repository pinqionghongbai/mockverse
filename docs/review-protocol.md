# 五轮审查协议（MockVerse 质量纪律）

> 来源：D12-D14 三个工作日、十轮收工审查的实战提炼（共抓出 5 个真 bug、
> 3 处文档口径错误、1 处事实断言挪用，补齐 3 个实证缺口）。
> **生效方式：每个 Day 的任务完成（编码+验证+归档提交）后自动执行，无需用户提醒。**
> 用户说"再检查一遍"是在补触发；协议生效后应该主动跑、用户只负责喊停。

---

## 一、触发与收口

- **触发**：一个 Day 的全部任务完成、归档提交推送之后（或用户明确要求时）。
- **收口条件**：**连续两轮无新发现**（D13 四查确立，五查为第一个无发现轮）。有产出
  就继续，不设硬性轮数上限；但实践中 3-5 轮必然收敛。
- **每轮纪律**：发现的问题**当轮修复 + 验证（compile/定向回归）+ 独立提交**，commit
  message 前缀 `D{X} {N}查: ...`；无法修复/不修的写明理由挂入 STATUS 挂起表。
- **每轮换视角**（核心）：同一视角连查两轮的边际收益断崖式下跌——五轮的价值
  在于每轮看的地方不一样。

## 二、五轮视角清单（按实战效果排序）

### 一查：证据一致性（文档数字 vs 实测证据）

- 日志/STATUS/演示脚本里的**每个数字**回查原始出处：DB 落库（agent_name/len/条数）、
  运行日志、API 响应。
- **综述性文档的汇总数字必须能从它自己的明细表重算出来**（D14 四查实录：协议文档
  头部战绩"8 个真 bug/十一轮"与其战绩表累计"5 个/十轮"对不上——跨 Day 战绩最容易
  在脑子里串账，写综述时当场重算，不引记忆）。
- 重点抓两类惯犯（D14 一查、D12 二查实录）：
  - **贴金**：两次独立测量被写成"与基线一致"（42 分 vs D11 基线 52，差 10 分超抖动）；
  - **漏计**：观测样本口径不全（D13 摇摆样本 1/3 → 实为 1/5，靠 DB 归因+文件时间戳重建）。
- 提交指针核对：tag 指向、commit 哈希与日志归档表一致。

### 二查：事实断言核验 + 修复代码重读

- **断言**：文档（尤其明日开工指引）里的"已有/已在"逐条实证——pom 依赖用
  `dependency:tree`，classpath 用 grep 双重确认。惯犯：**挪用**（把 lab 里的实证
  说成 monolith 的状态——D14 二查的 MCP SDK classpath 断言）。
- **重读**：上一轮（或本 Day）的修复代码**当别人的代码重读**；修 bug 时必做
  **同族病灶全库扫描**（`grep` 同类 catch/模式）——D13 二查修 onNext 漏 error
  回调、三查才补上的教训。

### 三查：错误路径语义验算 / 真故障注入

- **定律（D13-D14 反复验证）：happy path 一天就通，bug 全在错误路径。**
  杠杆点是错误分支的逐条语义验算，不是再跑 happy path。
- 优先**真注入**（能造的故障就造）：docker stop/start 数据库、错端口、断网。
  注入后验证三点：失败形态正确（不开半截流/不落脏数据）→ 恢复后自愈 → 无后患。
- 注入打不中的路径（时序窗口毫秒级）要**实验证明打不中**，不空口说"难注入"
  （D14 三查：docker stop 生效需数秒，赶不上 defer 落库的毫秒级窗口）。

### 四查：未覆盖角落（回归缺口 + 从未审查的链路）

- 本 Day 改了**共享依赖**（bean/配置/基类）后，盘点哪些消费方冒烟**没复跑**
  （D13 五查：加 streamingChatModel 后 prompt-ab 旧路径零实证，补跑闭环）。
- 挑一个从未被任何一轮碰过的模块做语义验算（回放/重建/幂等路径逐形态过）。

### 五查：收口轮

- 重复四查的扫尾逻辑；**无新发现**即与四查构成"连续两轮"，正式收口。
- 产出为"消掉一个没验证过的状态"也算收获（补一个实证缺口 = 减少一个未知）。

## 三、横切纪律（每轮都适用）

- **诚实标注**：未实测的路径写明原因（无法注入/成本超预算），与实测过的分开记。
- **口径可重建**：观测数据（路由摇摆率等）必须能从原始证据（DB/日志/时间戳）
  重建——应用日志会丢，DB 落库不会。
- **YAGNI 裁决**：查出来的不对称/不优雅不等于要修（D13 五查层 3 缺失定性为
  防御不对称不补码）——修不修的判断标准是"有没有真实失败形态走到那"。
- **修复本身也要 KISS**：修 bug 时的第一反应常引入重复（D13 四查初版 if/else
  两支重复调用，当场收敛）。
