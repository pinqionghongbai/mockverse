## TCP 三次握手与四次挥手

**三次握手**（建立连接）：
1. 客户端发 SYN，seq=x，进入 SYN_SENT。
2. 服务端回 SYN+ACK，seq=y，ack=x+1，进入 SYN_RCVD。
3. 客户端发 ACK，ack=y+1，双方进入 ESTABLISHED。

**为什么是三次而不是两次**：服务端需要确认客户端收到了自己的 SYN（即确认客户端的接收能力），同时双方要同步各自的初始序列号。两次握手时，一个延迟到达的旧 SYN 会让服务端误建连接并长期空等。

**四次挥手**（断开连接）：FIN → ACK → FIN → ACK。因为 TCP 是全双工，两个方向要分别关闭；服务端收到 FIN 后可能还有数据要发，所以 ACK 与自己的 FIN 分开发。

**TIME_WAIT 等待 2MSL** 的原因：保证最后一个 ACK 能到达对端（丢失时可重传 FIN）；让本连接的所有报文在网络中消亡，避免影响后续复用相同四元组的新连接。

## HTTP 与 HTTPS 的区别

- HTTP 明文传输，端口 80；HTTPS 在 HTTP 与 TCP 之间加了 TLS 层，端口 443。
- HTTPS 提供**加密**（防窃听）、**完整性校验**（防篡改）、**身份认证**（防冒充）。
- HTTPS 需要 CA 签发的证书，有握手开销（TLS1.3 已优化到 1-RTT，支持 0-RTT 会话恢复）。

**TLS 握手（简化）**：客户端发 ClientHello（支持的版本、密码套件、随机数）→ 服务端回 ServerHello + 证书 → 客户端验证证书链并用公钥加密预主密钥（或用 ECDHE 协商）→ 双方由随机数 + 预主密钥导出对称会话密钥 → 后续用对称加密通信。

**为什么用非对称加密协商、对称加密传输**：非对称加密安全但慢，对称加密快但密钥分发困难，两者结合各取所长。

## TCP 与 UDP 的区别

| 维度 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 确认重传、有序、去重 | 不保证 |
| 传输方式 | 字节流 | 数据报 |
| 头部开销 | 20 字节起 | 8 字节 |
| 拥塞控制 | 有 | 无 |
| 适用场景 | 文件传输、HTTP、数据库连接 | 视频直播、DNS、游戏、VoIP |

**TCP 的可靠传输机制**：序列号与确认号、超时重传、快速重传（三个重复 ACK）、滑动窗口流量控制、拥塞控制（慢启动、拥塞避免、快重传、快恢复）。

## 从输入 URL 到页面展示发生了什么

1. **URL 解析**：判断是搜索词还是合法 URL。
2. **DNS 解析**：浏览器缓存 → 系统缓存 → hosts → 本地 DNS 服务器 → 根/顶级/权威域名服务器，得到 IP。
3. **建立 TCP 连接**：三次握手；HTTPS 还要 TLS 握手。
4. **发送 HTTP 请求**：请求行、请求头、请求体。
5. **服务端处理并返回响应**：状态码、响应头、响应体。
6. **浏览器渲染**：解析 HTML 构建 DOM，解析 CSS 构建 CSSOM，合并成渲染树，布局（layout），绘制（paint），合成（composite）。
7. **断开连接**：四次挥手（HTTP/1.1 默认 keep-alive，可复用连接）。

## HTTP 常见状态码与缓存机制

**状态码分类**：1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误。

高频：200 OK、301 永久重定向、302 临时重定向、304 Not Modified、400 参数错误、401 未认证、403 无权限、404 不存在、429 请求过多、500 服务端异常、502 网关错误、503 服务不可用、504 网关超时。

**强缓存**：`Cache-Control: max-age=3600`（优先级高于 Expires），命中则不发请求，直接读本地。

**协商缓存**：强缓存失效后带 `If-None-Match`（ETag）或 `If-Modified-Since`（Last-Modified）询问服务端，未变更返回 304 且不带响应体。

**SSE 与 WebSocket 的区别**：SSE 基于 HTTP，单向服务端推送，自动重连，适合流式输出；WebSocket 是全双工独立协议，需要握手升级，适合双向实时通信。
